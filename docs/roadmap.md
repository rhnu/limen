# 实施路线图

## 当前状态与使用方式

`limen check` 与 `limen serve` 已可用：基础 YAML、业务 schema、本地 ESM、有界 JS 调度与 HTTP/1 JSON 网关已接通。
两个 API 共用独立客户端认证，完整非流管线按 provider → model 顺序运行，具备请求隔离、取消、观察预算与有界关闭。
应用是 workspace 根包，配置和脚本各有独立库。流请求和上游 SSE 仍明确拒绝。
本文件是唯一进度文档，只保存当前状态、剩余任务、阻碍与待验证项；长期契约见[设计基线](design.md)，
命令与依赖选择见[开发指引](development.md)。

下一步是 **M5：SSE 与四种传输组合**。当前已有 Windows 本机纯逻辑测试、隔离 JS 实验及本地合成 HTTP 上游实验；
覆盖单次发送、认证、顺序、失败提交、状态映射、资源拒绝、观察失败、deadline、断开、Ctrl-C 与退役退出。
不把这些结果视为 Linux、Docker、真实上游、TLS 接入或 GitHub runner 的执行证据。
JSON 连接期限已接线；Windows 系统写入排队未形成可靠的阻塞写证据，Linux 慢客户端实验仍待补充。
JS 自行捕获的 OOM 无法通过当前安全 API 可靠观察；内存上限仍生效，传播到宿主的 OOM 会退役。
该限制及不能取消 JS continuation、不能回滚闭包副作用的边界保留在设计中。

## 顺序与交付粒度

| 阶段          | 前置条件                 | 可交付结果                       | 阶段门槛                                   |
| ------------- | ------------------------ | -------------------------------- | ------------------------------------------ |
| M5 流与转换   | 已有非流管线             | 四种 JSON/SSE 组合               | 数据保留、背压、截断和流内错误成立         |
| M6 Linux 部署 | M5                       | 可部署容器及操作文档             | 目标平台构建与运行验收，无未解决的首版门槛 |

每个阶段拆成可独立评审的变化：依赖与类型、核心逻辑、适配接线、文档更新。
先用合成输入验证纯逻辑；运行时或部署验证单独安排，明确平台、范围与证据。
未来引入 HTTP、TLS 等依赖时重新核对注册表、发布记录、features、MSRV 和平台要求。

## M5：SSE 与四种传输组合

- [ ] 先调查现有 SSE 增量解析库，对照 WHATWG 规范；可复用解码能力与本项目语义层分开。
- [ ] 覆盖跨分块 UTF-8、CRLF/LF/CR、多行 data、注释和空事件边界；限制单事件大小。
- [ ] 实现 JSON→JSON、JSON→SSE、SSE→JSON、SSE→SSE 四条阶段次序，严格遵守设计第 7 节。
- [ ] 支持文本、refusal、function tool calls、多 choice、finish reason、usage；按 index 正确归并分片。
- [ ] 同形态保留合法未知字段；跨形态不支持的结构明确报错，不静默丢失数据。
- [ ] 流 hook 的 `replaceEvents` 一次设置、丢弃与拆分、后续步骤推进和输出上限。
- [ ] 默认别名只在形成对外表示时应用；JSON→SSE 保留 onResponse 显式修改的模型名。
- [ ] Rust 管理 framing、控制帧与 DONE；finish_reason 后继续读取 usage，缺 DONE 的 EOF 判为截断。
- [ ] 头未发送时用 HTTP/JSON 错误；SSE 已开始时发送约定流内错误并关闭，不伪造成功 DONE。
- [ ] 连接上游读取、下游写入和 hook 背压；取消停止本地推进，限制聚合字节、事件数及展开数量。

验收：使用最小合成事件覆盖四路径、分块边界、多个 choice/tool call、usage 尾块、重复替代输出、非法事件、
未知跨形态结构、迟到结果和截断。SSE→SSE 不因 onResponse 缓存整流；不得宣称 JSON→SSE 改善上游首包延迟。
网络断开、慢客户端和实际背压须补充运行验证，不能由纯解析测试代替。

## M6：Linux Docker 与首版交付

- [ ] 在所选 Linux 架构上验证 Rust、QuickJS C 构建与完整单元测试；确认 runtime allocator、TLS/CA 和动态库需求。
- [ ] 创建多阶段 Dockerfile、受控构建上下文、非 root 运行用户及配置目录只读挂载示例。
- [ ] 容器内显式监听 `0.0.0.0`；示例默认仅绑定宿主回环地址，内网开放由部署者明确选择。
- [ ] 验证包含共享模块的目录挂载、check、serve、SIGTERM、在途请求与 pending 清理、有限关闭预算。
- [ ] 以本地合成上游验证 JSON、SSE、认证、错误、断开与关闭；真实 provider 验证单独安排并记录范围。
- [ ] 接入镜像构建 CI；许可证、仓库可见性、镜像位置和发布权限明确后再接入推送与 release。
- [ ] 更新 README 为真实可执行的使用说明，核对所有首版契约与限制，关闭或明确记录剩余风险。

验收：产物能在目标 Linux 环境启动和关闭，配置与秘密不进入镜像层，客户端/上游认证独立，
进程异常恢复依赖部署重启策略且不重放生成请求。发布多架构、原生 Windows、性能指标均不自动包含在首版承诺中。

## 首版之外

自动重试、故障转移、热重载、上游模型发现、UI、Responses/Embeddings/Images/音频接口、
多租户、配额、宿主网络/文件 API、多 VM 池，以及完整多模态跨形态转换均不在当前实施范围。
JSON Pointer helper 仅在真实重复逻辑出现后评估，不阻挡主链路实现。
