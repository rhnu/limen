# 路线图

配置与认证、SQLite 请求记录、滚动日志、只读管理 API 及浏览器查看界面的契约见[设计](design.md)，使用入口见[记录与管理界面](features/management.md)。项目按稳定契约维护。

## 环境验收

- 在可用的 Linux Docker 环境验证本次变更：先验证生成器移至 `api/codegen/`、`pnpm patch` 及内嵌脚本打包后的构建上下文、补丁应用、cargo-chef 产物传递与镜像构建，确认不挂载 `sdk/` 也能导入 `limen:` 模块；再以 UID/GID 10001 启动，只读 config 和根文件系统、可写 data/logs，验证 schema 2 的请求与性能数据落库、重启恢复、TTFT/TPS 和阶段汇总、日志轮换、管理查询及 SIGTERM 在 25 秒宽限内退出。本机没有可用的 Linux Docker/WSL 运行环境，不能以 Windows HTTP 或 SQLite 隔离测试代替这项容器验收。
- 在允许创建符号链接的环境执行日志读取拒绝链接的隔离分支。本机 Windows 缺少创建符号链接权限，测试明确报告跳过；普通文件、目录拒绝、更名与截断已在 Windows 验证。

## 后续方向

- 配置写入单独设计：明确服务文件与业务脚本的编辑范围、校验和保存方式；不预设热重载。

现有 CI 与容器流程按稳定基线维护，上述验收只针对具体能力和容器边界变化。工具与检查命令统一见[开发指引](development.md)，本文只维护剩余任务。
