# 路线图

配置与认证、SQLite 请求记录、滚动日志、只读管理 API 及浏览器查看界面的契约见[设计](design.md)，使用入口见[记录与管理界面](features/management.md)。重构期间不部署，不维持阶段间配置、目录或 schema 兼容。

## 脚本与 Host 架构重构

按以下顺序细化并实施，每阶段完成行为验证后移除对应条目，将持续有效的约束归入设计或开发指引。保留公开脚本能力、单线程 VM 所有权、有界资源、provider → model 顺序和事务提交语义；内部接口直接替换，不增加兼容层或动态插件框架。

1. **收紧调用契约。** 用显式 hook 阶段、调用上下文和候选效果类型替代控制部分的字符串/任意 JSON 约定；正文和协议扩展保持开放 JSON。移除生产接口根据缺少 meta 切换普通草稿契约的分支，调整调度器测试入口，验证各阶段的输入输出、取消及提交。
2. **整理内嵌模块依赖。** 移除给每个公开模块隐式拼接同一 prelude 的方式，使用显式私有依赖和已有构建能力生成内嵌模块。继续由固定 limen: 注册表提供公开入口，核对构建、类型检查、部署输入及真实 VM 的缓存、未知模块拒绝和源码预算。
3. **编译原生策略执行计划。** 启动时显式绑定阶段、JS hook/原生执行器与状态模板，运行时消费已验证计划；新增策略必须穷尽声明阶段能力。保留管线位置的状态隔离、共享预算和批次提交，验证混排顺序、取消、超限及回滚。
4. **收窄 Host 服务依赖。** 分离通用加载结果与完整服务资源，由应用入口组合生成、管理与传输服务；服务构造只接收必要配置、状态及操作句柄。统一路由分类，验证认证分派、只读管理、离线复用和有界关闭。

异步 Host I/O API 不在本次新增功能范围。首次引入时须同时设计 VM 唤醒、实际操作容量、取消后的结果处理和关闭排空，不把返回 Promise 等同于完成生命周期接入。

## 恢复部署前的环境验收

- 在可用的 Linux Docker 环境验证本次变更：先验证生成器移至 `api/codegen/`、`pnpm patch` 及内嵌脚本模块后的构建上下文、补丁应用与镜像构建，确认不挂载 `sdk/` 也能导入 `limen:` 模块；再以 UID/GID 10001 启动，只读 config 和根文件系统、可写 data/logs，验证请求落库、重启恢复、日志轮换、管理查询及 SIGTERM 在 25 秒宽限内退出。本机没有 Docker/WSL，不能以 Windows HTTP 或 SQLite 隔离测试代替这项容器验收。
- 在允许创建符号链接的环境执行日志读取拒绝链接的隔离分支。本机 Windows 缺少创建符号链接权限，测试明确报告跳过；普通文件、目录拒绝、更名与截断已在 Windows 验证。
- 推送实施提交前，确认仓库外跟踪 `latest` 的自动更新已停用或固定镜像 digest；仓库内停用 webhook 不代表外部环境已完成此操作。
- 只有用户明确要求后恢复部署触发，并以该次部署使用的 schema 建立首个受支持基线。

## 后续方向

- 配置写入单独设计：明确服务文件与业务脚本的编辑范围、校验和保存方式；不预设热重载。

CI 的构建、测试和镜像发布继续保留，部署 webhook 维持注释。现有流程按稳定基线维护，上述验收只针对新增能力和容器边界变化。工具与检查命令统一见[开发指引](development.md)，本文只维护剩余任务。
